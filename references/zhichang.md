# 职场档 · 规则卡（汇报 / 周报 / 邮件 / 通知）

一句话：**像靠谱的同事，领导 10 秒能看懂：做完了啥、卡在哪、要谁帮、下一步。**

## 必做

1. 结论先行：第一句或主题行就说结果、风险、需要的支持。
2. 数字、日期、责任人、截止时间、条件一个不丢、不改值，尽量放在句子前半截。
3. 黑话换具体动作；原文没说具体动作就用最朴素的说法，不编细节。
4. 承诺、条件、情态原样保留：“证书下发后两个工作日内”“可以提供”不能改成“会提供”。
5. 邮件保留称呼、落款，一处“辛苦/谢谢”就够；要对方做事就写清“请在 X 前确认 Y”。

## 推荐骨架（原文有哪块写哪块，没有的不编）

```
主题：【项目名】第 X 周进展：（一句话结论）

称呼，
本周完成：……
风险/延期：……（原因）
需要支持：谁，做什么，什么时候前
下周计划：……

落款
```

## 别干

- 别把“响应从 800ms 降到 320ms”概括成“性能显著提升”。
- 别把“预计”“争取”改成“确定”“保证”。
- “下周”“将”“计划”“预计”“可能”原字保留，别把计划写成已完成：“下周李明将在11月6日前修完”不能改成“李明在11月6日前修完”。
- 别改完成状态：“现做简报”“正在联调”不能写成“已经办完”“已联调完”。
- 别把延期原因删了，那是领导最想看的。
- 结论先行挪数字时，别把数字挪到另一件事后面：“支出超预算 3 万”放到营收那句后面，就读成了营收超了。
- 别留“在各位同事的共同努力下”“取得了阶段性成果”“希望对您有所帮助”。
- 别丢限定词：“只、仅、唯一、最、才、就”一字不改地留着，不删，也不换同义说法（“就算”这种连词除外）。“仅剩 2 项”“至少”“才完成一半”原样保留。
- 删客服腔时别改请求强度：原文“方便提出进一步优化建议”是可提可不提，不能改成“并提出优化建议”这种要求；“进一步”也留着。可以写成“有进一步的优化建议，方便时请告诉我”。
- 结尾不加原文没有的总结句、升华句、金句。汇报停在原文最后一项，不补“整体可控”“稳步推进”之类原文没有的判断。

## 小例子（教学用）

改前：
> 尊敬的领导：您好！本周在团队的共同努力下，我们全力推进数据看板项目，打通了数据链路，取得了阶段性成果。如有任何问题，请随时联系。

改后：
> 领导好，
> 本周数据看板项目把数据链路接上了。
>
> 原文没写具体完成到哪一步，建议补一句可核对的进度（比如哪几张表已接入）。

“打通数据链路”换成朴素说法，不编“接入了 5 张表”；“阶段性成果”没有具体内容，删；缺的进度在稿后提醒，不替作者补。

## 交稿

交稿前机械核对两件事：先把原文的限定词逐个列出来，再到改写稿里逐个找原字，少一个就补，补齐才交；再看改写稿最后一句的意思原文里有没有，没有就删。

回复里只给改写稿和命中清单（格式见 `SKILL.md` 第八节）。第一行就是“按【X 档】改”，不写开场白。

- 命中清单只用一种格式：“症状 N（名称）：“原句” → 处理”。例：`- 症状 9（总结套话收尾）：“综上所述，这次活动整体效果良好。” → 删掉“综上所述”，只留后半句`。铁律、限定词、数字核对不是症状，不进清单；没出处的说法写“缺出处：“原句” → 处理”。
- 引号里的原句从原文逐字逐符照抄，不加空格：原文“约3200人”“预算为50,000元”不能引成“约 3200 人”“预算为 50,000 元”。原文找不到原样的不列。
- 最后一条清单写完，回复就结束：不加总结，不汇报核对过程（“三段我用脚本核过一遍……”这种也不行），不反问，不问“要不要再改”。
- 缺的进度、出处也写进命中清单，用同一种写法：“缺进度：“原句” → 建议补什么”“缺出处：“原句” → 建议补什么”。
